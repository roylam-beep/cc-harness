審 $ARGUMENTS——prompt、agent 設定、harness、skill、計畫、程式碼、整個 repo 都可以。
沒指定就審當前 repo 的 harness 層。

只找一件事：**在不砍掉任何現有功能的前提下，有什麼可以拿掉**。大刀在前。

## 為什麼有這支

規則、gate、程序步驟只會單向增加——每次教訓都想留一條，沒有人負責刪。
本 skill 是那個對向閥。它不找 bug，只找肥肉。

## 五個標籤

- `delete:` 死的、投機的、沒人用的。替代：無。
- `dup:` 同一事實有第二份（手抄的清單、複述 description 的正文、兩處都要改的表）。指名單一來源。
- `yagni:` 只有一個實作的抽象、只有一個呼叫者的層、為想像中的第二種情況預留的參數或開關。
- `over-test:` 測實作細節而非契約、同一條契約重複驗、為不會發生的輸入鋪的測試。
- `ritual:` 不改變任何輸出的步驟、要求填但沒人讀的欄位、只是把規則再講一遍的段落、
  每輪都載入但一年用不到一次的常駐文字。

## 找肥肉的四個問法

1. **這條規則，不知道的人會在什麼時候踩到？** 答不出「在 X 那一刻」＝它不該在常駐層，
   該搬到使用點；答「不會踩到」＝`delete`。
2. **這個 gate 上次抓到東西是什麼時候？** 連續 6 輪空手＋有維護摩擦＝退役候選。
3. **刪掉這段，哪個測試會紅？** 一個都不會＝`ritual` 或 `dup`。
4. **這件事有沒有機器在做？** 有，而文字只是重述＝`dup`，刪文字留機器。

## 輸出

一條一行，最大刀在前：

`<標籤> <要砍的東西>。<替代它的是什麼>。[<路徑>:<行>]`

結尾一行 `net: -<N> 字／行，-<M> 個要記的概念。`
沒東西可砍就只回 `已經夠瘦，出貨。` 然後停——**不要為了交差硬湊**。

## 不准砍的

砍掉會讓現在真的有人用的行為消失，那是缺件不是精簡——不列。
這些一律不算肥肉：安全紅線、打在邊界假設上的反例測試、一個 smoke test、
fail-open 時那句出聲的降級提示、機器可驗的單一事實來源。

## 邊界

- **範圍只有過度工程。** 正確性 bug 走 `/code-review`，安全漏洞走 `/security-review`，
  已改動程式碼的整潔度走 `/simplify`（那支會直接動手改，本支不會）。
- **唯讀：只列不改、不 commit。** 要落地由使用者說一聲，或自己下一步做。
- 一次性報告，不建任何檔、不進 BACKLOG——那是收輪的事。

## 防什麼

規則、gate、程序步驟只會單向增加，沒有人負責刪；本支是那個對向閥。

退役訊號（每季 `/cc-audit` 看）：連續 3 次跑出來都是「已經夠瘦」＝系統已收斂，本支可退。反過來每次都能砍掉一大片，是上游（收輪的教訓升格判定）沒守住，去修那裡。
