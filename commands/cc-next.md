給推薦，對象是 $ARGUMENTS。留空就推薦「現在該做什麼」；含 `--red` 就跑第 4 步。

**你的工作是替使用者想出一個推薦，而且敢選。** 事實你查，推薦你給，拍板使用者做。

## 1. 查現況

- 留空：`git status`、`git log --oneline -10`、`BACKLOG.md`、`handovers/` 最新一份、本次對話。
- 給參數：參數提到的檔案與相關程式；上面那組只在跟這個決策有關時才讀。

查得到的事實不拿去問人。

## 2. 列候選，最多 2 個

留空時，「階段交界」也是候選：這個 session 該繼續、`/compact`、`/clear`、寫交接單（`/cc-handover`），還是派子 agent。
先排除「繼續」——它不花成本也不丟東西，只有 context 已經塞滿、或接下來換主題時才不選它。

## 3. 前提不足

查完還缺**只有使用者知道、而且會改變推薦**的事 → 用一次 `AskUserQuestion` 問 **1 題**
（2 個選項，建議答案放第一個，`label` 結尾加 `(Recommended)`）。
1 題問不完 → 不硬推薦，回一句「前提太多，先跑 `/cc-grill`」就停。

## 4. 紅隊（只有 `--red`）

派 1 個 `Agent`（`subagent_type: Plan`，它的工具集沒有 Write／Edit），prompt 給推薦、理由與第 1 步的證據，
要它找出推翻推薦的最強理由。被推翻就換推薦；沒被推翻，把它最強的那條寫進「改變推薦的條件」。

## 5. 輸出

固定五欄，每欄一行：

```
推薦：<做什麼>——<理由，最多兩句>
替代：<另一個做法>——<跟推薦差在哪，一句>（沒有就寫「無」）
回頭：<雙向門＝做了可撤回／單向門＝撤不回>，<撤回要做什麼>
工作量：<小／中／大／特大>（session 輪數）
改變推薦的條件：<一句可檢查的條件>
```

然後用一次 `AskUserQuestion` 問「要照這個推薦做嗎」，選項「照做」與「不要」。

- 照做 → 同一輪直接開始做，範圍就是「推薦」那一行，不順手擴大。
- 不要 → 停。

## 規矩

- **按「照做」之前唯讀**：不改檔、不 commit；子 agent 只查不寫。
  不用 `disallowed-tools` 硬擋：它一載入就擋到整輪結束，按了照做也寫不了。
- **一定要選。**「看情況」「兩個都可以」不算推薦；分不出高下就把分界寫進「改變推薦的條件」，還是選一個。
- **只給 1 個推薦**，不列清單、不排序、不加「另外也可以考慮」。
- 跟 `/cc-grill` 的分界：grill 是 Claude 問使用者、問到雙方理解一致；本支是使用者問 Claude、一次給推薦。

## 防什麼

使用者每次做決定前都要問「你建議怎樣」，拿到的卻是一份列滿選項、不敢選邊的比較，
還得再追問一輪才有答案。
